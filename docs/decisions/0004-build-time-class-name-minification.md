# ADR-0004: ビルド時のクラス名短縮（頻度順の全単射リネーム）

- **Status**: Accepted
- **Date**: 2026-07-04
- **Deciders**: yutaura

## Context

クラス名のバイトコストは「名前の長さ × 出現回数」で決まり、ベンチマーク（bench/RESULTS.md）では class 属性が HTML サイズの主要因だった。現行の 9 文字内容ハッシュ（`bc` + base36）は「全クラスが揃う前に衝突なく名前を決める」ために必要な長さだが、ビルドの最終段階では全クラスの一覧が確定しており、このマージンは不要になる。

## Decision

クラス名を **2 層** で扱う。

1. **内部名（dev / 変換時）**: 従来どおり内容ハッシュ（`bc...`）。重複排除・クロスファイル収束・HMR の安定性はこの層が担う
2. **出力名（build 最終段階）**: `generateBundle` で全クラス確定後、**使用頻度の高い順に短い名前（a, b, ..., z, aa, ...）へ全単射リネーム**する。頻度は JS チャンク内の静的出現回数を代理指標とする

デフォルト有効。`bestCss({ minifyClassNames: false })` で無効化できる。

ベンチマークでの効果: class 属性 3,589 → 1,875 bytes（-48%）、合計 gzip 1,729 → 1,494 bytes（-14%）。

## Alternatives Considered

- **内容の単純さに応じた可変長ハッシュ**: 名前の長さと出力サイズの関係は「出現回数」で決まり、内容の複雑さは無関係。またハッシュを短くすると衝突確率が上がり、衝突＝別スタイルの誤適用という致命的な故障モードを持つ
- **宣言単位の共有（セレクタリストへの括り出し）**: 理論上限が raw 27%（431 bytes）で、セレクタリストのオーバーヘッドと gzip の反復圧縮を考慮すると実効はさらに小さい。カスケード順序の変化リスクも伴うため、費用対効果でリネームを優先した
- **最初から短い名前を割り当てる**: ビルド前は全クラス集合が確定せず、ファイル単位の変換だけでは全単射を保証できない

## Consequences

### Positive

- class 属性 -48%。HTML / CSS 両方の全指標で tailwind（合計 gzip 比 51%）と CSS Modules（同 78%)を下回った
- 衝突チェックが全数確認になるため、ハッシュ長の安全マージン自体が不要になる

### Negative

- クラス集合が変わると頻度順位がずれて広範囲の名前が変わる（ビルド間の名前安定性がない）。SSR した HTML を長期キャッシュする構成では注意が必要（そのための無効化オプション）
- プロダクションのクラス名から dev の名前を辿れない。必要になったらマッピングファイルの出力で対応する
- チャンクの文字列置換にソースマップが追従しない
- ユーザーが手書きした 1〜2 文字のグローバルクラスと衝突し得る（ドキュメントで注意喚起する）

### Neutral

- 頻度は静的出現回数であり実行時の描画回数ではないが、全クラスが 1〜3 文字に収まるため順位の精度がサイズに与える影響は小さい
