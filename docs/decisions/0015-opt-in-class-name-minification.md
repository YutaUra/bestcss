# ADR-0015: クラス名短縮を opt-in（デフォルト無効）にする

- **Status**: Accepted
- **Date**: 2026-09-18
- **Deciders**: yutaura

## Context

ADR-0004 でクラス名の頻度順短縮を導入し、**デフォルト有効**とした（ベンチで class 属性 -48%、合計 gzip -14%）。その後の運用で、デフォルト有効であることのコストが見えてきた。

短縮名（`a`, `b`, ...）は **バンドル全体の使用頻度順** で決まる。つまり 1 つのクラスの名前が、そのクラス自身とは無関係な変更で動く:

- コンポーネントを 1 つ足す / 消すと頻度の順位が入れ替わり、既存クラスの名前がずれる
- ずれた名前は SSR した HTML と配信 CSS の両方に載るため、長期キャッシュがまとめて失効する
- 同じ理由で、SSR 構成では client → server のビルド順とリネーム表の共有（ADR-0006）が**必須の制約**になる。順序を守れない環境（webpack モードの Next.js のように client / server が並列に走る）では短縮そのものが使えない

一方 ADR-0014 でハッシュ入力を正規化し、内容ハッシュ名（`bc` + 7 桁）は「書式ゆらぎにも依存しない内容アドレス」になった。**短縮しない選択肢の品質が上がった**ため、どちらを既定にするかを再検討する余地が生まれた。

## Decision

**`minifyClassNames` のデフォルトを `false` にし、短縮を opt-in にする。**

- 既定では内容ハッシュ名（`bc...`）のまま出荷する。内容アドレスなのでビルドを跨いで安定し、SSR した HTML と配信 CSS は表の共有もビルド順の制約もなしに一致する
- サイズを詰めたいビルドで `minifyClassNames: true` を明示する。ADR-0004 の仕組み自体は変えない
- CSS の重複排除・レイヤー順の権威宣言は短縮の有無によらず常に行う（短縮とは独立した機能のため）

「デフォルト有効 = 何もしなくても速い」より「デフォルトで予測可能 = 名前が勝手に動かない」を採る。サイズ最適化は測って意図的に有効化する種類の判断であり、暗黙に効いていて副作用（キャッシュ失効・ビルド順の制約）だけが後から発覚する形は避ける。

## Alternatives Considered

- **デフォルト有効を維持する**: charter の差別化要因 2「HTML / CSS 両方のサイズ最適化」が初期状態で効く利点はある。しかし副作用（無関係な変更で名前が動く / SSR でビルド順が必須になる）が暗黙で、踏んだときの原因特定が難しい。効果は実測できるので opt-in でも失われない
- **頻度順ではなく安定した順序で短縮する（例: クラス名のソート順）**: 名前は安定するが、頻度順であることが短縮の効果そのもの（出現回数の多いクラスに短い名前を割り当てる Huffman 的な発想、ADR-0004）。効果を捨てて安定性を得るなら、そもそも短縮しない方が単純
- **本番ビルドのみデフォルト有効、SSR 構成ではデフォルト無効**: 条件付きのデフォルトは「自分の環境で有効なのかどうか」が読めず、キャッシュ戦略を立てる側にとって最悪。真偽は 1 箇所で明示されるべき
- **ライブラリ配布だけデフォルト無効**（現状の運用）: ADR-0013 は既に `minifyClassNames: false` を要求している。デフォルトが逆だと「ライブラリでは切る」という例外を覚える必要があり、既定を無効にすればこの例外が消える

## Consequences

### Positive

- 既定でクラス名がビルドを跨いで安定し、SSR した HTML と配信 CSS の長期キャッシュが無関係な変更で失効しない
- 既定では SSR 構成の client → server ビルド順とリネーム表共有が不要になり、「表がない」エラーを踏む経路が消える
- ライブラリ配布（ADR-0013）の「短縮を切る」が既定と一致し、覚えるべき例外が 1 つ減る
- 短縮のテキスト置換（JS チャンク / CSS アセットへの文字列置換）が既定で走らなくなり、利用者の文字列を誤って書き換える経路も既定では消える

### Negative

- **初期状態ではサイズ最適化が効かない**。charter の差別化要因 2 は opt-in の機能になる。ベンチが示す -48% / gzip -14% は `minifyClassNames: true` を書いた場合の数値であり、README / ドキュメントで明示する必要がある
- 既に `minifyClassNames` を指定せず短縮を享受していたプロジェクトは、アップグレードで出力が大きくなる（設定 1 行で戻せる）
- ベンチマーク（bench/run.mjs）と SSR の example は、測定対象・CI での経路維持のために明示的な opt-in が必要になった

### Neutral

- ADR-0004 の仕組み（頻度順の全単射リネーム、`generateBundle` での適用）は変更していない。変わったのは既定値のみ
- Turbopack は元からアセット後処理フックがなく短縮非対応だったため、この経路の挙動は変わらない
