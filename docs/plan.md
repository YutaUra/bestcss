# Plan — best-css

このプロジェクトの段階的な計画。フェーズの進行や見直しに応じて更新される。

## 現在のフェーズ

**Phase 1: MVP — `` css`...` `` が Vite + React で動く**

M3（Vite プラグイン統合）まで完了。次は M4: dev サーバー / HMR の検証と対応 → MVP 完了。

## MVP 定義

tsx 内の `` css`...` `` タグ付きテンプレートをビルド時に抽出し、CSS ファイルとして分割出力し、生成したクラス名をコードに注入できる。対象は Vite + React のみ。サイズ最適化と styled 構文は MVP に含めない。

完了条件:

- [ ] `` css`...` `` で書いたスタイルがビルド時に `.css` ファイルとして抽出される
- [ ] 抽出された CSS はモジュール単位で分割され、使用箇所からのみ読み込まれる
- [ ] 生成されたクラス名が衝突しない（スコープが保証される）
- [ ] ランタイムに CSS 生成コードが一切含まれない（バンドル解析で確認）
- [ ] examples の Vite + React アプリが dev / build の両方で動く
- [ ] dev サーバーで HMR が機能する

## フェーズ計画

### Phase 1: MVP（css タグの抽出と分割出力）

**目標**: Vite + React で `` css`...` `` によるスタイリングが end-to-end で動く

**完了条件 (Definition of Done)**: 上記「MVP 定義」の完了条件をすべて満たす

**想定タイムライン**: TBD（次回更新時に決定）

### Phase 2: サイズ最適化

**目標**: 思想の核心である「HTML / CSS 両方のサイズ最適化」を技術検証・実装する。差別化要因なので styled 構文より先に取り組む

**完了条件**:
- [ ] 複数モジュール間で重複する CSS 宣言がマージ・共有される
- [ ] tailwind 方式（アトミック class 列挙）と比較して HTML サイズが小さいことをベンチマークで示す
- [ ] 既存手法（tailwindcss / CSS Modules 素朴出力）との HTML + CSS 合計サイズ比較レポートがある

### Phase 3: styled-components 構文

**目標**: `` styled.div`...` `` API を追加し、DX を完成させて dogfooding 可能な状態にする

**完了条件**:
- [ ] `` styled.<tag>`...` `` でコンポーネントを定義できる（ゼロランタイムを維持したまま）
- [ ] 作者の実プロジェクトへの導入が開始されている

### Phase 4: Vite 以外への展開

**目標**: unplugin 化などにより Next.js 等の Vite を用いないプロジェクトへ統合できるようにする

詳細は Phase 2〜3 の結果を見て具体化する（TBD）。
