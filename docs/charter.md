# Charter — best-css

このプロジェクトのアイデンティティを定義する文書。**変更には ADR が必須**。

## 存在意義 (Why)

best-css は、既存の CSS ライブラリが抱えるトレードオフを **同時に** 解消することを目指す CSS ライブラリである。panda-css / tailwindcss / unocss / vanilla-extract / CSS Modules / styled-components の代替を狙う。

既存ライブラリはそれぞれ何かを犠牲にしている:

| 既存ライブラリ | 得たもの | 犠牲にしたもの |
|---|---|---|
| tailwindcss / unocss | ゼロランタイム・CSS サイズ | HTML の class 肥大、生 CSS 文法 |
| styled-components | コロケーション・生 CSS 文法 | ゼロランタイム |
| vanilla-extract / panda-css | ゼロランタイム・型安全 | 生 CSS 文法（TS オブジェクト記法） |
| CSS Modules | ファイル分割・生 CSS 文法 | コロケーション（ファイル往復が発生） |

best-css は以下の 5 つの価値を **全部取り** する:

1. **当たり前にゼロランタイム** — 実行時に CSS を生成するコードを一切出荷しない
2. **HTML / CSS 両方のサイズ最適化** — tailwind のような class name の肥大を防ぎつつ、CSS の重複も排除する
3. **コロケーション（css-in-js style）** — JSX（将来的には html / vue も）の中に CSS を置くことで、スコープが明確になり、ファイル往復がなくなる
4. **自然なファイル分割** — 単一の巨大 CSS ファイルではなく、CSS Modules のように自然に分割され、適切に読み込まれる
5. **生 CSS 文法** — TS オブジェクト記法ではなく、タグ付きテンプレート内に生の CSS に近い文法で書くことで、既存の CSS 資産（知識・スニペット・ツール）をそのまま活用できる

## 想定ユーザー (Who)

- **第一目標**: 作者（yutaura）自身のプロジェクトで使うこと
- **将来**: 思想が実証できたら OSS として広く公開する

## やること (In Scope)

- JSX 内の生 CSS 記述（`` css`...` ``）をビルド時に抽出し、CSS ファイルとして分割出力するコンパイラ
- HTML（class 名）と CSS（ルール重複）の両面でのサイズ最適化
- Vite プラグインとしての統合
- 将来的な Vite 以外（Next.js 等）のビルド環境への展開

## やらないこと (Out of Scope) ⚠ 重要

- **UI コンポーネント集**: Chakra UI / MUI のような完成済みコンポーネントは提供しない。あくまでスタイリング基盤に徹する
- **ランタイム動的スタイル**: props の値から実行時に CSS を生成する機能は持たない（CSS カスタムプロパティで代替する）。ゼロランタイムを崩す機能は一切入れない
- **独自プリプロセッサ構文**: Sass 的な独自拡張構文（mixin・関数など）は追加しない。生 CSS（＋ネスト等の標準仕様）に準拠し続ける
- **コンポーネント生成 API**（`` styled.div`...` `` 風）: best-css の責務は「CSS → クラス名」に限定する。コンポーネント抽象はユーザーランドに任せる（[ADR-0005](decisions/0005-drop-styled-components-api.md)）

## 将来のスコープ拡張余地

- デザイントークン / テーマ機構: 当面は CSS カスタムプロパティに委ねるが、将来的な検討対象からは除外しない
- html / vue など JSX 以外のテンプレートへの対応

## 隣接プロジェクトとの境界

現時点で隣接リポジトリはなし。パッケージ分割（core / vite-plugin など）は本リポジトリ内の monorepo で管理する（[architecture.md](architecture.md) 参照）。

## 成功条件 (Success Criteria)

- 作者自身のプロジェクトで tailwindcss 等の既存ライブラリを置き換えて常用できている
- 使っていて既存ライブラリに戻りたいと感じない（コロケーション・生 CSS・サイズの価値が体感できている）
- （将来）OSS として公開し、外部ユーザーが導入できる状態になっている

## 撤退条件 (Sunset Criteria) ⚠ 重要

- **技術的仮説の破綻**: 「ゼロランタイム × 生 CSS 文法 × サイズ最適化」の同時成立が技術的に不可能、または実用的でないと判明したら撤退する
- **上位互換の登場**: 既存ライブラリ（panda-css 等）や新ライブラリが同じ思想を先に実現したら、そちらに移行して凍結する
- **利用停止**: 作者自身のプロジェクトで 6 か月以上使われなくなったら凍結する

## 後継への移行パス

撤退時は、思想が最も近い既存ライブラリ（その時点での panda-css / vanilla-extract 相当）への移行を想定する。生 CSS 文法で書かれたスタイルは CSS Modules へ機械的に書き出せるため、最終手段として CSS Modules への export を移行パスとする。

## 前提と制約

- ライセンス: OSS 公開を見据え MIT を予定（TBD: 公開時に確定）
- ビルド時変換が前提のため、バンドラー（まず Vite）へのプラグイン統合が必須である
